# Plan: Boards — cross-source personal PM (smart-views-first hybrid)

Date: 2026-06-16 · Branch: `feat/gitdeck-shell`

## Vision (from the user)
> "eigne boards machen kann wo ich cross repo/clickup etc issues managen kann. das soll
> ein persönliches project management tool sein aber im gedanken an gitdeck das es open source is"

Decisions locked with the user:
- **Model:** Hybrid, **smart-views first**. Columns are primarily LIVE cross-source
  filters that auto-fill. Manual pin/move into a column overrides the smart result
  (built on top, secondary).
- **Columns:** fully **user-defined** per board (add / rename / reorder / delete),
  persisted in the DB.

## Architecture split
- **Backend (Rust/Tauri, mobile-capable — NO sidecar):** persists boards, columns
  (each with an opaque smart-filter JSON), and manual card placements. CRUD only.
  The filter JSON is **opaque** to Rust (stored as TEXT / serde_json::Value).
- **Frontend (TS):** the **smart-filter engine** runs client-side over a unified item
  pool (GitHub issues + PRs already fetched per account + local todos; later
  Codeberg/ClickUp). One predicate per column. Manual placements overlay/override.
  This keeps it reactive, offline-friendly, and avoids N live API calls per column.

Rationale: data is already client-side (list_issues/list_pull_requests/list_tasks);
filtering there is cheap, testable (vitest), and mobile-friendly.

## Data model — migration `0003_boards.sql`
```sql
CREATE TABLE boards (
    id TEXT PRIMARY KEY NOT NULL,
    name TEXT NOT NULL,
    position INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
CREATE TABLE board_columns (
    id TEXT PRIMARY KEY NOT NULL,
    board_id TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    position INTEGER NOT NULL DEFAULT 0,
    filter TEXT NOT NULL DEFAULT '{}',   -- opaque smart-filter JSON; {} = manual-only
    created_at TEXT NOT NULL
);
CREATE INDEX idx_board_columns_board ON board_columns(board_id);
CREATE TABLE board_cards (             -- manual placements / overrides (secondary)
    id TEXT PRIMARY KEY NOT NULL,
    board_id TEXT NOT NULL REFERENCES boards(id) ON DELETE CASCADE,
    column_id TEXT NOT NULL REFERENCES board_columns(id) ON DELETE CASCADE,
    item_key TEXT NOT NULL,            -- "todo:<id>" | "gh-issue:<acct>:<owner/repo>#<n>" | "gh-pr:..."
    position INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL
);
CREATE INDEX idx_board_cards_board ON board_cards(board_id);
CREATE UNIQUE INDEX idx_board_cards_board_item ON board_cards(board_id, item_key);
```

## Smart-filter JSON shape (documented; opaque to Rust, interpreted in TS)
```ts
interface SmartFilter {
  item_types?: ("issue" | "pr" | "todo")[];  // default: all
  state?: "open" | "closed" | "all";          // default: open
  providers?: ("github" | "codeberg" | "clickup")[];
  account_ids?: string[];                      // optional account allowlist
  repos?: string[];                            // owner/name allowlist (exact)
  labels?: string[];                           // any-of, case-insensitive
  assignees?: string[];                        // any-of logins; "@me" special-cased later
  text?: string;                               // free text over title/repo/author
}
```
`{}` ⇒ matches nothing (manual-only column).

## Phase A — backend (Rust only; this dispatch)
- `0003_boards.sql`.
- core: `Board`, `BoardColumn`, `BoardCard` structs (pure serde) + store methods:
  create/list/rename/delete/reorder boards; create/update(name+filter)/delete/reorder
  columns; place_card/remove_card/list_cards. `filter` carried as serde_json::Value.
- service: thin pass-throughs + DTOs (`BoardDto` with nested columns, `CardDto`).
  A `get_board(id)` returns the board with its columns (and manual cards) in order.
- Tauri commands: `list_boards, create_board, rename_board, delete_board,
  reorder_boards, create_column, update_column, delete_column, reorder_columns,
  place_card, remove_card`.
- TDD: store + service tests; keep `cargo test --workspace` green.
- Does NOT touch frontend / api.ts (avoid collision; wired in Phase B).

## Phase B — frontend (after Phase A)
- api.ts wrappers for the board commands + `Board/BoardColumn/BoardCard/SmartFilter` types.
- The TS smart-filter engine `resolveBoard(columns, pool, manualCards)` → resolved
  columns, **vitest-tested**. Pool = issues + PRs + todos from the active account(s).
- Nav: add **Boards** section. Board list + create. Board view: horizontal columns,
  add/rename/reorder/delete column, per-column **filter editor** (state/type/repo/label/text),
  cards rendered with the existing IssueCard-style treatment. Manual drag → place_card
  (override). Our minimal-sharp style; i18n en+de.

## Out of scope (for now)
- Codeberg / ClickUp providers (pool is GitHub + todos until those land).
- Real-time/auto-refresh polling (manual refresh + on-mount fetch is fine).
